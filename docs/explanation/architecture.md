# Architecture

How the pieces fit, and why. Each section links the decision record that holds the full argument.

## The shape of the product

A user opens a PDF, marks it, pins shapes together, and exports a crop. Three behaviours are separate capabilities:

- **Display a PDF** on the canvas (`@h2-fe/pdf-viewer`).
- **Pin tool** (`@h2-fe/pin`): a pin that carries the shapes it sits on.
- **Camera tool** (`@h2-fe/camera`): a persistent crop frame with PNG, clipboard and SVG export.

Two pages host them. Home (`/`) opens a document. The viewer route (`/viewer`) shows the canvas.

## Layers

```
apps/web                      routes: home, viewer. Thin wrappers, business logic only
  ├─ libs/web/features/*      capabilities: pdf-viewer, pin, camera
  ├─ libs/web/ui              web-scoped UI (viewer top bar); also the web Storybook stage
  └─ libs/shared/ui           design system, @h2-fe/ui; its own Storybook, published to Chromatic
```

Imports run downward only. Nx tags enforce the scope boundary: `scope:web` may import `scope:web` and `scope:shared`; `scope:shared` imports only `scope:shared`. That is the only lint-enforced constraint. The rule that pin, camera and pdf-viewer do not import each other is a convention held in review ([ADR 0011](../decisions/0011-feature-pattern.md)).

Everything, including libs, is generated by Nx and tagged. Dependencies are declared once, in the root `package.json`.

## Features are capabilities, routes are hosts

A feature is something you can name and ship. A route is a page and may compose several features. So home is not a feature lib; it is a route in `apps/web`. Pin and camera are libs with no route at all.

The route owns glue. The viewer route:

1. reads the `File` that home passed through navigation state,
2. rasterises it with a TanStack Query hook (`usePdfPages`),
3. builds the extension list,
4. renders `PdfViewerScreen`, which is a dumb component: props in, handlers out.

Screens never fetch. See [ADR 0011](../decisions/0011-feature-pattern.md).

## Canvas extensions

Pin and camera add behaviour to a canvas they do not own. Each exports a factory returning an object shaped like the viewer's `CanvasExtension`: tools, shape utils, bindings, overlays, UI overrides, an in-front component, and an `onMount` hook.

The viewer owns the only `<Tldraw>`. It merges all extensions into one set of props. The extension libs and the viewer never import each other; the route is the one place they meet, and TypeScript checks the structural match there.

Why this way: each capability stays testable on a plain `<Tldraw>` in its own stories, and the viewer stays ignorant of what it hosts. What a capability needs to know about the viewer comes in as a factory option (`canAttach`) or a route prop (`retainPageBounds`). See the [reference](../reference/canvas-extension.md).

## PDF pages are locked image shapes

Each visible page is rasterised by pdf.js into an image asset and shown by tldraw's stock `image` shape, locked, with id `shape:page-N`. Pages that leave the viewport are deleted and rebuilt on return, so memory is bounded by the viewport rather than the page count. Each new raster gets a new asset id, because updating an image's `src` in place is debounced by tldraw ([ADR 0012](../decisions/0012-pdf-pages-as-image-shapes.md)).

Consequences you will meet:

- Export works for free, since a stock image shape exports with its asset.
- Pins cannot attach to pages, because eviction would delete the shape and its bindings. The route passes `canAttach: (shape) => !isPdfPageShape(shape)`.
- A crop frame must keep the pages under it rendered. The route passes `retainPageBounds={getCropFrameBounds}`.
- Locked shapes ignore `updateShapes` and `deleteShapes` unless wrapped in `editor.run(..., { ignoreShapeLock: true })`.

Known limits are recorded in [the task 2 spec](../specs/task-2-pdf.md) (open performance criteria) and [the task 4 spec](../specs/task-4-camera.md) (open questions).

## Two styling systems

Chakra styles the chrome we own: top bar, dialogs, home screen. tldraw's own CSS variables and component overrides style the canvas UI. A scoped class (`h2-canvas-theme`) maps Chakra tokens onto tldraw's `--tl-color-*` variables after `tldraw.css`. The app's color mode is pushed into the editor with `editor.setColorMode`; the editor is not remounted ([ADR 0013](../decisions/0013-tldraw-chakra-theme-bridge.md)).

Do not wrap tldraw internals in `chakra()`: tldraw drops `className` on some of them, so it does nothing.

## Spec first, test first

Each task begins with a spec of falsifiable acceptance criteria. A failing test comes before the code, and a criterion is ticked only when a test fails without it ([ADR 0005](../decisions/0005-sdd-and-tdd.md), [specs](../specs/README.md)). Stories with play functions are the component tests ([ADR 0007](../decisions/0007-storybook-scope.md)).

## Quality gates

`bun run gate` runs lint (oxlint, type-aware), format (oxfmt), typecheck, unit tests, builds, Storybook builds and Storybook play tests with axe, on affected projects only. Hooks (lefthook) run a fast subset locally; CI runs the full gate. See [Run the gate and fix a red one](../how-to/run-the-gate-and-fix-a-red-one.md) and [ADR 0008](../decisions/0008-lint-split.md) (module boundaries run inside oxlint; see its addendum).
